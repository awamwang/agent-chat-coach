# 迭代优化方法与常见失败模式

> 好 prompt 是改出来的。本文件给出"改三轮"套路与对症药方。

## 改三轮套路
1. **第一轮：能跑**——要素齐全（角色+任务+约束+格式），先拿到可用输出。
2. **第二轮：可控**——加示例 / 限格式 / 收口径，让结果稳定复现。
3. **第三轮：精调**——按使用反馈微调语气、长度、侧重点，沉淀成模板。

## 对症药方（看结果说话）
| 你看到的问题 | 改法 |
|---|---|
| 输出太长/太短 | 加字数约束："不超过 N 字"或"展开到 N 点" |
| 格式乱跑 | 显式给结构："用 Markdown 三级标题 + 表格"或"返回严格 JSON" |
| 风格不对 | 加角色 + 风格参照："模仿{某作者/某媒体}的口吻" |
| 瞎编事实 | 加约束："不确定就明确说明，禁止编造数据/引用" |
| 抓不住重点 | 加优先级："最重要的三点优先""先结论后论证" |
| 每次不一样 | 加示例(few-shot) + 固定输出格式，降低随机性 |
| 太泛泛 | 补上下文 + 具体受众 + 明确交付物 |

## 进阶技巧
- **思维链（CoT）**：复杂任务加"请先列出步骤，再逐步完成"。
- **角色卡固化**：把表现好的角色/约束存成可复用 system prompt 模板。
- **A/B 对照**：同一任务两版变体并跑，挑稳的那版固化。
- **负向指令**：明确"不要做 X"往往比"要做 Y"更省字、更可控。
