# 五层黄金架构与十大铸造模式（知识截止：2026-09）

> 用途：铸造/诊断任何工程级提示词的方法论底座。2026 年全网主流共识（CSDN、腾讯新闻、DevPress 等 2026-02~09 公开实践文章交叉验证）：高质量提示词普遍可分解为五层，缺层是输出失控的首要根因。

---

## 一、五层黄金结构

### L1 身份层（Role）
定义模型是谁、专业到什么程度、行为边界在哪。
- 反面：「你是一个助手」——泛化身份 = 泛化输出。
- 正面：「你是一位有 10 年 B2B SaaS 经验的增长分析师，专注 ARR 归因，只回答增长相关话题。」
- 要素清单：专业领域 + 年限/深度词 + 服务对象 + 边界（领域外话题怎么拒答）。

### L2 任务层（Task）
明确交付物与完成标准。动作动词开头：生成 / 分析 / 改写 / 检查 / 输出。
- 反面：「帮我分析一下」。
- 正面：「基于下方 CSV 数据，计算各区域 Q2 销售额同比变化率，输出 TOP3 增长驱动因素及 3 条可执行建议。」
- 要素清单：动作动词 + 输入源 + 交付物形态 + 数量/质量标准。

### L3 约束层（Constraint）
划定禁止行为、兜底话术、信息来源边界。这是压缩模型输出概率空间、迫使注意力离开「默认套话」的秘密武器。
- 必备三类：内容约束（禁止编造，仅基于给定素材）、风格约束（语气/受众/长度）、禁忌约束（禁用词表、禁用句式，如「不要用『革命性』『赋能』开头」「感叹号不超过 1 个」）。
- 兜底声明：「素材中不存在的内容，统一回复：暂无相关参考资料，无法解答。严禁编造。」

### L4 上下文层（Context）
提供素材锚点：背景资料、历史数据、术语表、受众画像。无素材时用 `{变量}` 占位并附变量表，让使用者填入。
- 原则：素材放提示词内（长素材放末尾并编号），临时对话上下文不依赖。

### L5 输出格式层（Format）
指定返回结构，便于直接使用或程序解析。
- 要素：结构类型（Markdown 标题层级 / JSON Schema / 表格 / 列表）、段落与长度、重点标注方式（加粗规则）、是否先给结论。
- 反面：让模型自由发挥 → 每次格式漂移。

> 层序变体：复杂任务可把 L2 提到最前（指令前置，模型对最近的显式内容权重更高）；强制 JSON 输出的场景把 L5 前置到 L1 之后。

## 二、十大铸造模式

### P1 目标委托（Target Delegation）
对强推理模型写「成功标准 + 红线」，不写逐步操作。例：「交付标准：可直接发布的成稿；红线：不得出现未核实的数据。」
适用：复杂开放任务、能力强的模型。逐步指挥反而锁死模型路径。

### P2 假设透明（Assumption Transparency）
信息不足时不穷追：按最佳实践补全 → 显式列「本次关键假设清单」→ 用户「第 X 点改成 Y」秒改。零阻塞 + 可回溯。

### P3 最少提问（Minimal Clarification）
最多 1 轮澄清；合并 3~5 问；每问附 2~3 候选。判断标准：缺了必然方向性返工才问。

### P4 祈使句手册（Imperative Manual）
全部指令用动词开头（Read X / Extract Y / Write Z）。删除「请你」「希望你能」「麻烦」等客套——它们稀释指令权重。

### P5 显式打分门禁（Scored Gate）
100 分制 + 维度权重 + 阈值（如 ≥95 交付）+ 不通过则按扣分项迭代。防「自我感觉良好」式产出。本技能 scripts/prompt_score.py 即此模式的脚本化。

### P6 溯源标注（Provenance Tagging）
关键事实与结论带出处；时效内容带「知识截止」日期；未知标「待确认」。防编造、可审计。

### P7 安全三闸门（Security Gates）
密钥一律 `${VAR}` 占位不硬编码；权限最小化（只声明必需工具）；外发/删除/支付类动作先请求确认。

### P8 分步推理（Chain-of-Thought Anchor）
复杂推理任务显式要求「先分步推理，再给最终结论」，可显著降低逻辑幻觉；格式敏感任务则要求「先给结论，再给理由」，避免解析失败。

### P9 少样本锚定（Few-Shot Anchor）
给 1~3 个高质量输入→输出示例，模型快速对齐格式与质感。示例质量 > 示例数量；示例必须含边界案例（如一条「无答案」样例）。

### P10 风格锚定（Style Anchoring）
多轮/多产出的文风一致性：固定风格前缀（语气、受众、禁用词）+ 固定质量后缀（自检清单：交付前核对 X/Y/Z）。

## 三、铸造对象为「系统提示词」（Agent/技能）时的特化

当任务本身是给某个 Agent、智能体、技能写系统提示词，在五层之上追加：

1. **触发层**：何时激活（覆盖用户自然说法 ≥90% 的触发词写进 description/开头）。
2. **流程层**：编号 Stage/Phase 流水线，每阶段有明确产出物，禁止跳步。
3. **规范层**：输出格式与合规要求内嵌写死，不靠模型自觉。
4. **边界层**：铁律清单 + 异常降级路径（联网失败/字段不明/需求模糊/中断续跑）。
5. **权限最小化**：仅声明必需工具；不写越权指令。

## 四、常见翻车与修正速查

| 症状 | 根因 | 修正（命中层） |
|---|---|---|
| 输出泛泛而谈、像百科 | L1 身份泛化 | 身份具体到领域+年限+边界 |
| 每次格式都不一样 | L5 缺失 | 显式指定结构与长度 |
| 一本正经编造数据 | L3 无信息边界 | 加「仅基于素材，不知道就说不知道」 |
| 答非所问、目标漂移 | L2 无交付物与标准 | 动词+交付物+数量标准 |
| 语气客套、模型撒娇 | P4 未执行 | 全文改祈使句，删敬语 |
| 长任务中途失忆 | 无阶段产出物 | 每阶段落盘中间产物（P8+流程层） |
| 硬编码密钥/隐私 | P7 未执行 | 全部改 `${VAR}` 占位 + 变量表 |
| 示例带偏节奏 | P9 示例低质 | 换 1~2 个高质示例并含边界案例 |
