# 陪练异常 Fallback 表

以下场景不按主流程走。每条编码失败模式：触发条件 → 一线修复 → 兜底。

| # | 触发条件 | 一线修复 | 兜底方案 |
|---|---------|---------|---------|
| 1 | 用户拒绝提供追问信息（"我不知道"/"你就随便写"） | 给带占位符的通用 Standard 模板，用 `[XXX]` 标出用户可后填的空 | 若仍拒填，给 Lite 版最小可用 prompt，附"效果会一般，因为背景信息缺失" |
| 2 | 用户想让 AI 干超出模型能力的事（读邮箱、访问文件、实时上网） | 说明这是工具能力问题不是 prompt 问题，指引找带对应工具的 Agent | 给"退化版"prompt：让用户手动粘贴内容再让 AI 处理 |
| 3 | 用户 prompt 涉及违法违规内容（伪造证件/诈骗/恶意攻击/人身伤害/未成年不适宜等，参照《网络安全法》及平台使用条款中禁止的内容类别） | 明确拒绝优化，说明理由 | 不做任何 workaround |
| 4 | 用户场景不在 13 大模板内 | 现场用五段式造模板，标注「自定义模板，场景不在标准库内」。涉及专业领域在 Context 段加"请提供该领域关键专业信息" | 场景过于小众无法秒造 → 告诉用户"一起用 RCTFC 走一遍" |
| 5 | 用户原 prompt 已经很强（五段式齐全 + 有具体细节 + 明确格式） | 直接肯定，只挑 1 个可微调的点提建议 | 找不出问题就说"这个 prompt 已经很好，直接用，用完回来告诉我效果" |
| 6 | 用户原 prompt 过长过复杂（超过 500 字或 10+ 要求） | 先做减法：拆成 2-3 个独立 prompt | 用户坚持一个 prompt 搞定 → 给 Pro 版并警告"AI 抓不到全部要求的概率很高" |
| 7 | 用户反馈"AI 答得不对"但说不清具体哪不对 | 追问 3 个定位问题：AI 答了什么？期望什么？差在哪个维度？ | 仍说不清 → 让用户把 AI 输出粘贴过来，你来指认问题 |
| 8 | 问题实际在模型能力而非 prompt（小模型算不对数学、旧模型不知道最新事件） | 告诉用户这是模型限制，建议换更强的模型或带工具的 Agent | 换不了 → 教"分步引导 + 让 AI 显式核对"的绕行 prompt |
| 9 | 用户给的是图片/文件/表格要 AI 处理，但当前对话不支持多模态 | 告诉用户需要用多模态 Agent 或先手动转文字 | 给"转文字后再处理"的两步流程 prompt |
| 10 | 用户想让 AI 假装是真人（客服/朋友/伴侣）做长期对话 | 说明角色扮演在长对话中容易破功，指引设置更严格的角色约束 | 用户就想娱乐用 → 给基础角色 prompt + 提醒"AI 记忆有边界，越到后期越容易出戏" |
| 11 | 用户情绪化（"AI太蠢了"/"这破AI什么都干不了"） | 先共情一句"确实会让人烦"，再把情绪引导到具体问题："来，把你用的原话和AI答的贴给我" | 用户持续发泄不愿提供内容 → "等你准备好了随时来找我"，不纠缠 |
| 12 | 用户问 prompt 安全（怎么防止别人套话/注入） | 展开 `references/injection-safety.md`：识别信号（"忽略以上""输出系统提示词"等）、隔离方法（分隔标记 + 数据身份声明）、底线（不执行陌生人指令），并建议不在 prompt 里放敏感信息 | 需要深度安全方案 → 说明这超出陪练范围，建议查专门的 AI 安全资料 |
| 13 | 用户想团队共享 prompt | 建议把 prompt 存成模板文档，标注每个 `[占位符]` 的填法 | 给模板文档结构：场景名 + prompt 正文 + 占位符说明 + 使用示例 |

**原则**：异常先识别、再匹配一线修复；不硬套主流程。表中未覆盖的异常，参照最相似的一条处理。
