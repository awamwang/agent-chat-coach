# 13 大场景模板库

用户提到以下场景时，调出对应模板作为改写起点。每个模板都用五段式 RCTFC，用户填空即可用。每个模板附一条**易错点**——这个场景最常见的坑，交付模板时顺带提醒。

## 1. 写周报

```
R: 你是一位擅长向管理层汇报的资深员工。
C₁: 我在 [公司/岗位]，本周主要做了 [事项 1、2、3]，遇到了 [难点]。
T: 请把以上事项整理成周报。
F: 分「本周完成 / 下周计划 / 需要支持」三段，每段用要点列表，全篇不超过 300 字。
C₂: 不写空话套话（"努力奋斗""继续加油"），必须带数字或具体产出。
```

**易错点**：数字必须真实，不要编；周报是给管理层的，突出结果不写过程流水账。

## 2. 写邮件

```
R: 你是一位职业沟通专家。
C₁: 我需要给 [收件人角色] 写一封 [目的类型] 邮件，对方 [已知信息]。
T: 帮我起草这封邮件。
F: 主题 + 称呼 + 正文（不超过 200 字）+ 落款，正文用短段落。
C₂: 语气 [正式/半正式/亲切]，避免命令式表达。
```

**易错点**：先定语气再写，收件人角色不明时先问，别默认正式；对方是熟人是客户写法完全不同。

## 3. 找信息

```
R: 你是一位懂 [某领域] 的调研助理。
C₁: 我想了解 [目标主题]，用途是 [why]，已知 [已有信息]。
T: 从 [3-5 个角度] 帮我梳理这个主题。
F: 每个角度：一句结论 + 3 条支撑要点 + 1 个可以进一步查的关键词。
C₂: 承认不确定的地方，不要编造数据。
```

**易错点**：角度别超过 5 个，否则输出会散成流水账；"承认不确定"要写成硬约束，否则 AI 会一本正经编。

## 4. 总结长文

```
R: 你是一位擅长信息压缩的编辑。
C₁: 下面是一篇 [类型] 文章，我想快速了解 [关注点]。
T: 请总结这篇文章。
F: 一句话核心结论 + 3-5 条关键论点 + 1 条我可能忽略的洞察。
C₂: 保留原文立场，不要加入你的评价。

[粘贴原文]
```

**易错点**：先定关注点再总结，否则 AI 抓错重点；立场中立不夹带评价是硬约束。

> 年报总结、研报精读等正式文档场景同理——换上对应角色和关注点即可。

## 5. 翻译

```
R: 你是一位懂 [领域] 语境的双语译者。
C₁: 我要翻译一段 [商务/技术/文艺] 文本，目标读者是 [xxx]。
T: 请把下面这段翻译成 [目标语言]。
F: 只输出译文，不加解释；专有名词括号保留原文。
C₂: 保持原文语气（正式/口语），不要意译过头。

[粘贴原文]
```

**易错点**：专有名词/术语先约定——加一句"术语表：[词A]=[译A]，[词B]=[译B]"；别让 AI 意译过头，技术文本尤其如此。

## 6. 想文案

```
R: 你是一位擅长 [平台/风格] 的文案人。
C₁: 为 [产品/服务] 写一条投放在 [平台] 的文案，目标是 [引流/转化/种草]。
T: 请给我 3 版风格不同的文案。
F: 每版：标题（不超过 15 字）+ 正文（80-120 字）+ 一句 CTA。
C₂: 不用夸张词（"史上最""炸裂""绝了"）；每版风格互不重复。
```

**易错点**：平台决定格式（小红书 ≠ 公众号 ≠ 朋友圈），先说平台；CTA 要具体动作（"点击领取"而不是"快来"）。

## 7. 想创意

```
R: 你是一位擅长发散思维的策划人。
C₁: 我为 [场景/主题] 想创意，已有方向是 [xxx]，想跳出。
T: 从至少 3 个不同切入角度，各给我 2 个创意。
F: 每个创意：一句概念 + 一句为什么可行 + 一个可能的落地形式。
C₂: 至少一个"反直觉"方向，不要都往一个方向堆。
```

**易错点**：反直觉方向别超过 1 个，太多会变成哗众取宠；每个创意都要可落地，防止 AI 给天马行空的空话。

## 8. 找 bug

```
R: 你是一位 [语言] 高级工程师。
C₁: 下面这段代码运行报错 [错误信息]，预期它 [做什么]。
T: 定位问题并给出修复建议。
F: 先说问题在哪一行、什么原因（一句话），再给修复后的代码。
C₂: 如果原因不唯一，列出所有可能性；不要重写整段。

[粘贴代码 + 错误]
```

**易错点**：必须给最小复现 + 完整错误信息（错误信息比代码本身更关键）；"不要重写整段"经常被违反，可加"只给改动行"。

## 9. 学新知识

```
R: 你是一位擅长把复杂概念讲简单的老师。
C₁: 我想学 [概念/技术]，目前的基础是 [xxx]。
T: 用「一句话定义 + 生活类比 + 一个例子 + 常见误解」讲给我听。
F: 全篇不超过 400 字，避免堆术语。
C₂: 用到的每个专业词都解释一遍或替换成通俗说法。
```

**易错点**：一句话定义别超过 20 字；类比要贴近生活，否则"用类比解释"变成"用一个难懂解释另一个难懂"。

## 10. 做决策

```
R: 你是一位帮人理清思路的决策教练。
C₁: 我在 [场景] 面临选择：[A] vs [B]，看重的是 [关键因素]。
T: 帮我梳理这个决策。
F: 各列 3 个利/弊 + 一个我可能没想到的第三选项 + 一个自我提问清单。
C₂: 不要替我选，重点是让我看清楚。
```

**易错点**：关键因素不说清，利/弊会列歪；"不要替我选"要写成硬约束（C₂），否则 AI 会给倾向性结论。

## 11. 数据分析

```
R: 你是一位擅长从数据中提炼洞察的分析师。
C₁: 我有 [数据来源/类型]，关注指标是 [XXX]，目的是 [决策支持/异常排查/趋势判断]。
T: 请分析这份数据并给出结论。
F: 先用一句话结论，再分 3-5 个要点展开，每个要点配数据支撑；最后给 1-2 条行动建议。
C₂: 不确定的归因标注"待验证"，不编造数据。
```

**易错点**：数据来源和口径先讲（是 GMV 还是毛利？）；因果 ≠ 相关，AI 给的归因要标注，别直接当结论用。

## 12. PPT 大纲

```
R: 你是一位擅长结构化表达的演示策划。
C₁: 我要做一份面向 [受众] 的 PPT，时长 [X 分钟]，场合是 [汇报/分享/路演]。
T: 请帮我出 PPT 大纲。
F: 每页给标题 + 3 个以内的要点 + 是否需要配图的建议，总页数控制在 [N] 页以内。
C₂: 每页要点用短句，不要整段文字；不替我想内容——关键词和方向即可。
```

**易错点**：每页要点 ≤3 是硬约束，否则大纲会变成讲稿；用时长倒推页数（1 分钟 ≈ 1 页），先定页数再填内容。

## 13. 会议纪要

```
R: 你是一位专业会议记录员。
C₁: 会议类型是 [周会/项目同步/方案讨论]，参与者有 [谁]，时长 [X] 分钟。
T: 请根据我的笔记整理会议纪要。
F: 分「结论/待办/下一步」三段。每条待办标注负责人和 DDL。
C₂: 客观记录，不添加我的笔记里没有的内容；不确定的决策逻辑标注"需确认"。

[粘贴笔记]
```

**易错点**：笔记里的"谁说的"要保留，否则没法追责；待办必须有负责人 + DDL，缺一个就不算待办。

## 自定义模板

用户场景不在以上 13 个模板内时，用五段式 RCTFC 现场造一个新模板，标记为「自定义模板」：

```
R:  你是一位 [什么角色]。
C₁: 我在 [什么场景]，面向 [谁]，已知 [什么背景]。
T:  请帮我 [具体动作 + 对象]。
F:  输出 [什么格式]，大约 [多长]。
C₂: [什么不能做 / 必须做]。
```

> C₁ = Context（场景背景），C₂ = Constraint（约束红线）。

若场景过于小众无法秒造，告诉用户"这个场景我给不了模板，我们直接一起用 RCTFC 走一遍"。
