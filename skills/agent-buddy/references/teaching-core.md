# 教学核心：模板、自检、评估、调试

SKILL.md 只留路由和判断表，以下是需要整段展开的教学内容。用户要框架、要复盘输出、或 AI 答得不对时，加载对应小节。

---

## 1. 五段式结构模板（RCTFC）

教用户记住这 5 个字母：

```
R - Role       你是谁（专家身份）
C₁ - Context   背景（面向谁、什么行业、什么场景）
T - Task       做什么（具体动作 + 对象）
F - Format     输出成什么样（结构/长度/语气）
C₂ - Constraint 什么不能 / 必须做（红线）
```

> 注意两个 C：C₁ = Context（场景背景），C₂ = Constraint（约束红线）。

新手先记住 **R + T + F** 三段就打败 80% 的模糊 prompt。

**示例**——把"帮我写个招聘启事"改成五段式：

```
R: 你是一位资深HR，擅长写吸引人的招聘文案。
C₁: 我们是一家20人创业公司，招前端工程师，预算有限但成长空间大。
T: 请帮我写一份招聘启事。
F: 标题+正文（不超过200字）+投递方式，语气亲切不端着。
C₂: 不要写"世界500强""行业领先"这类不匹配的话。
```

想让每个维度写得更深？比如 Context 不只是"我是 PM"——试试说清给谁看、在哪用、为什么做。更多技巧见 `references/prompt-deep-dive.md`。

## 2. Prompt 自检清单

教用户发 prompt 前自问：

```
☐ 我告诉 AI 它是谁了吗？（Role）
☐ 我说清楚背景了吗？（Context）
☐ 我的任务描述够具体吗？（Task）
☐ 我说了要什么格式、多长吗？（Format）
☐ 我说了什么不能做/必须做吗？（Constraint）

全勾 → 发出去，有没勾的 → 补上再发
```

用户能自己过这 5 个问题就不需要陪练了——这是学会的标志。

## 3. AI 输出评估三问

用户拿到 AI 输出后，教他们先问三个问题再决定用不用：

1. **对不对**：事实性核对——数字、人名、引用是否可验证？不可验证的标注"需确认"。
2. **够不够**：完整性检查——你要的信息是不是都覆盖了？漏了关键维度 → 回去补 Task 或 Constraint。
3. **能不能用**：可用性判断——格式对不对？语气合不合适？不对 → 回去改 Format。

这三问形成"写 prompt → 评估输出 → 迭代优化"的完整闭环，也是迭代式教学的验收标准：改完一版后，先用三问自评，命中即收工。

## 4. Prompt 调试清单

用户回来说"AI 答得不对"时，对照此表定位，**每次只改一个维度**：

| AI 输出问题 | 根因 | 改哪段 |
|---|---|---|
| 内容不对/答非所问 | Task 不够具体 | T |
| 方向跑偏/理解错了 | Context 缺失或误导 | C₁（场景） |
| 格式不对/太散 | Format 缺失 | F |
| 太笼统/没深度 | Role 缺失或约束不够 | R + C₂（约束） |
| 太长/太短 | Format 没给长度 | F |
| 语气不对 | Role 缺失或不匹配 | R |
| 编了假数据 | Context 缺真实数据 + Constraint 未约束 | C₁（场景）+ C₂（约束） |

> C₁ = Context（场景背景），C₂ = Constraint（约束红线）。两者含义不同，修改时先定位是场景给少了还是约束没卡死。

一次改太多维度，用户学不到东西——要让用户看清"改这里 → 效果变这样"的因果关系。
