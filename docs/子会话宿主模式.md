# 子会话宿主模式（试验 v0）

> 状态：试验性 · 2026-10-29 · **未改动任何程序文件**（`server/` / `web/` / `scripts/` 均原样）
> 定位：让「宿主桥」挂在一个**子会话**上，而不是挂在当前（初始）会话。

## 1. 为什么要有这个模式

面板桥（`render_bridge_view`）挂在当前会话时，会同时承担两件事：主线对话 + 长挂等单。判定任务插进主线，
上下文被判定内容挤占，隔天回看也乱。

子会话宿主把这两件事拆开：

- 初始会话只负责「我在跟用户说话」；
- 收到口令才唤一个子会话去接单，答完即退，不污染主线。

## 2. 与现有两种宿主的关系

| 宿主类型 | 注册方式 | hostId 从哪来 | 适合 |
|---|---|---|---|
| 面板桥 | `render_bridge_view` | `ui/initialize` 的 `hostContext.workbuddy.sessionId` | 当前会话随手判，判定卡片在对话流里 |
| 无面板宿主 | `host.mjs --id <x>` | 命令行显式指定 | 后台常驻、脚本化、跨会话在线 |
| **子会话宿主（本模式）** | `host.mjs --id <x>`，**在子会话里跑** | 命令行显式指定 | 按需起、与主线隔离 |

### 关键约束（这条路为什么必须走 CLI）

子会话与初始会话共享同一条 MCP 连接，`sessionId` 相同。所以子会话若调 `render_bridge_view`，
只会注册成**和主线同一个宿主**，拿不到第二个身份。

能拿到独立身份的只有 `host.mjs` 的显式 `--id`——它走的是 `POST /mcp` 的 `await_question`，
宿主身份完全由参数决定，与会话无关。**这是本模式成立的全部依据，别改成调桥视图。**

## 3. 口令（文字命令）

在初始会话里说下面任一句，执行本技能的 Agent 就按第 4 节 spawn 一个子会话宿主：

- `/子会话`
- `起子会话挂桥`
- `叫个子会话接单`

补充约定：

- 口令由 Agent 识别，**没有程序解析器**，也不新增 CLI 子命令；
- 带数字视为连挂单数：`/子会话 3` → 在子会话提示词里写「循环订阅 3 轮」，v0 的 `host.mjs` 本身不支持 `--rounds`；
- 说「收子会话」/「撤桥」= 让子会话停止订阅（它本来答完就退，多数情况无需操作）。

## 4. 初始会话的标准动作

1. **确认桥在线**
   ```bash
   node "<skill-root>\scripts\bridge.mjs" --check
   ```
   未在线先跑 `node "<skill-root>\scripts\bridge.mjs"`。`--init` 有致命项就停在这里报给用户。

2. **spawn 子会话**：用 Agent 工具，类型 `general-purpose`，**后台运行**，名字 `coach-sub`。

3. **贴提示词模板**（整段复制，替换 `<子会话序号>`，第一个留空）：

   ```
   你是「子会话宿主 coach-sub<序号>」。任务：以独立宿主身份挂到本地常驻桥 8913，接一单判定后退出。

   环境（固定，不要改）：技能目录 <skill-root>；桥已在线 http://127.0.0.1:8913；不重启桥、不改任何程序文件。

   1) 前台运行订阅（timeout 设 70000，waitMs 必须小于它）：
      node "<skill-root>/scripts/host.mjs" --wait --id coach-sub<序号> --label "教练 · 子会话<序号>" --wait-ms 55000
      命中会打印「=== 收到一条待判问题 ===」、问题 id 与原文，然后退出（码 0）。
      若退出但没命中（空转到工具超时），原样重跑，最多 3 次。
   2) 提取问题 id 与「---- 消息原文 ----」到「---- 原文结束 ----」之间的正文。
   3) 按 providers/ 与 rules.md 的口径判定，把完整答复写入
      <skill-root>/workspace/_bridge/sub-answer-<id>.md
   4) 提交：node "<skill-root>/scripts/reply.mjs" --id <id> --file <上面的文件>
   5) 用 SendMessage 向 main 报告：问题 id、原文、reply 输出、踩坑记录。
   ```

4. **确认注册成功**（spawn 后 4–10 秒）：
   ```bash
   curl -s http://127.0.0.1:8913/web/state
   ```
   `hosts[]` 里出现 `coach-sub` 且 `online:true` 才算成功；没有就去看子会话的报错。

5. **告诉用户怎么发**：网页宿主下拉里选「教练 · 子会话」，再发送——不选则按服务端兜底逻辑
   投给最近活跃的宿主，可能仍落在主线上。

## 5. 子会话的标准动作

固定五步，顺序不能换：**订阅 → 取 id 与原文 → 按口径判定写文件 → `reply.mjs` → 回报**。

纪律：

- 只答一单就退，不自行续订（连挂多单由初始会话在提示词里写明循环）；
- 不重启桥、不 kill 进程、不碰 `server/` `web/` `scripts/`；
- 判定口径与主线完全一致（`providers/` + `rules.md` + `styles.md`），子会话是**执行体**，不是第二套标准；
- 重复提交由服务端静默忽略（`duplicate`），不要重写答案。

## 6. 边界与已知缺陷

| 项 | 现状 |
|---|---|
| 生命周期 | **一次性**：答完即退，宿主 30s 后掉线（`HOST_ALIVE_MS`），再发需重新唤 |
| 接单窗口 | 只在 `--wait-ms`（≤ 60000）内有效；窗口外提交，服务端按「无在线宿主」拒绝（HTTP 400） |
| 工具超时 | Bash timeout 必须 **大于** `--wait-ms`，否则空转被掐、白等一轮 |
| 串台 | `answer` 事件广播给**所有** SSE 客户端，页面不按 `hostId` 过滤——多宿主时另一窗口也会看到答案。修它必须动 `web/coach.html`（主路径，本模式不碰） |
| 并发 | 多个子会话用不同 `--id`（`coach-sub`、`coach-sub-2`…）互不冲突 |
| 安全 | 桥默认只听 `127.0.0.1`；子会话不获得任何额外权限 |

## 7. 排错表

| 症状 | 先查 |
|---|---|
| 网页下拉看不到子会话 | `curl /web/state` 有没有该 `--id`；`host.mjs` 输出有没有报错（多半是桥没起） |
| 发送报「无在线宿主」 | 子会话已退出（一次性），重新唤一个 |
| 子会话收到问题但网页没反应 | `reply.mjs` 是否成功打印；`--id` 是否是那个问题 id |
| 子会话空转超时 | `--wait-ms` 是否 ≥ 工具 timeout；两者调成 55s / 70s |
| 主线被判定内容挤占 | 说明子会话没起成，问题落回主线了——按第 4 节第 4 步复查 |

## 8. 验证记录（2026-10-29 17:24–17:25，47s）

| 环节 | 证据 |
|---|---|
| 注册 | `/web/state` 4s 内出现 `coach-sub / 教练 · 子会话`，与 `coach-local` 并列 |
| 投递 | `POST /web/message {hostId:"coach-sub"}` → `ok:true, pendingCount:1` |
| 接单 | 命中问题 `37030a7a-584b-415e-83cb-adbed5ca0adb`，订阅进程退出码 0，未重跑 |
| 回推 | `reply.mjs` 成功，`answeredCount` 0→1，`pendingCount` 归 0 |
| 网页可见 | SSE 收到 `{"type":"answer","hostId":"coach-sub","hostLabel":"教练 · 子会话",...}` |

结论：**可行，零主程序改动**。
